  1. Introduction

  1.1 Purpose
  This document defines the requirements for the first version (MVP) of Rovem, a browser-
  based 3D game that teaches Grade 9 Kinematics and Dynamics through building and
  driving a rover.

  Terms used in this document: MVP is the minimum viable product, meaning the first
  playable version. FR is a functional requirement, something the game must do. NFR is a
  non-functional requirement, a quality the game must have, such as performance. TBD
  means to be decided. Knowledge is the in-game currency, counted in points and earned
  by clearing questions: one cleared required question earns 10 points. A guest is a student
  who plays without an account. An account is an optional sign-in with an email address and
  a password.


  1.2 Scope
  Students build a rover from a few components, predict how it will behave, drive it through
  missions, and see the physics explained. The MVP has one terrain, three missions, one
  rover model built from parts, scenario questions, and Knowledge to unlock parts and
  missions. Students can play as guests or save their progress to an account. Everything
  else is listed in Section 6 as future work.

  The physics is defined in full in the companion Physics Model Specification. Proposed
  component and surface values are in the Component Values sheet. The database is
  described in the companion Data Model document.

  1.3 Learning objectives (MVP)
  By the end, a student should be able to:

       Relate distance, time, speed and acceleration.
       Explain how mass and driving force affect acceleration (F = ma).
       Explain how friction affects motion and stopping.
       Explain why a body moves at constant speed when the forces on it balance (Newton's
       first law).
       Combine these ideas to solve a practical problem.

  These objectives were checked against the Grade 9 Kinematics and Dynamics chapters
  by a Grade 9 physics teacher.


  1.4 Learning loop
  Predict → Experiment → Observe → Explain → Retry


  2. Overall Description

  2.1 Users
  Primary users are Grade 9 students. Secondary users are teachers and evaluators who
  review the concept.


  2.2 Constraints
       The game runs in a desktop web browser and needs no installation.
       The game is built by a single developer, so the scope must stay small.
       The physics must follow textbook formulas, not the default behaviour of the game
       engine.
       The physics uses g = 9.8 m/s², as the textbooks do. Numerical questions use g = 10 m/s²
       so answers are whole numbers, as in classroom practice.
       The interface language is English.


  2.3 Assumptions
       Students have already met Newton's laws and friction in class, and the game reinforces
       and applies them.

       The terrain is flat, gravity is constant, and there is no air resistance in the MVP.

  3.3 Controls

     ID            Requirement

     FR-6          The student can steer left and right, apply throttle
                   and apply brake. There is no reverse. Throttle and
                   brake levels rise steadily from zero to full while the
                   key is held and fall steadily back to zero when it is
                   released. The maximum brake force is fixed for
                   each rover model. Surface friction is a separate,
                   external effect and is not part of the brake. If
                   throttle and brake are held together, the brake
                   applies and the throttle is released.

     FR-7          Controls use a small number of simple inputs so
                   they can later be adapted to touch screens.

     FR-27         Steering changes the rover's direction, not its
                   speed. A stopped rover does not turn. The driving
                   screen shows speed in m/s and the direction of
                   travel as an arrow.



  3.4 Physics model

     ID            Requirement

     FR-8          Acceleration is net force divided by mass (a = Fnet
                   / m), where net force is the driving force minus
                   rolling friction and any braking force. Braking and
                   friction only slow the rover; they cannot push it
                   backward. A stopped rover stays stopped unless
                   the driving force is greater than rolling friction.

     FR-9          Rolling friction depends on the surface, the chosen
                   wheels and the rover's weight (F = μR). Grip, set by
                   the surface and the wheels, limits the driving and
                   braking force the tyres can pass to the ground.
                   Asking for more makes the wheels slip, and the
                   screen shows it.

     ID            Requirement

     FR-10         Speed and distance are calculated with the
                   equations of motion over short, fixed time steps in
                   which force is constant, so results match the
                   textbook relations exactly.

     FR-11         Every implemented variable has the same effect
                   every time. No part changes performance purely to
                   make the game more entertaining.

     FR-28         Each motor has a top speed. At top speed the
                   motor only balances friction, so net force is zero
                   and the rover moves at constant speed (Newton's
                   first law).

     FR-29         The physics uses g = 9.8 m/s², a fixed time step that
                   does not depend on the frame rate, and no random
                   values.

  3.6 Feedback and results

     ID           Requirement

     FR-14        After each run, the game shows the measured
                  results: distance, time, average speed, top speed
                  reached, average acceleration, and stopping
                  distance and time where relevant.

     FR-15        The game explains why the outcome occurred,
                  using pre-written explanations filled in with the
                  run's own values, and shows the formula used,
                  rather than only reporting success or failure.

     FR-16        The game shows the student's predictions next to
                  the actual result.

  3.7 Scenario questions

     ID            Requirement

     FR-17         Each mission has three required scenario-based
                   multiple-choice questions. They are shown before
                   a run, as predictions, and never while the rover is
                   moving.

     FR-18         Questions test reasoning (for example "will it stop
                   sooner or later on ice?"), not definition recall.

     FR-19         Each question has a pre-written correct answer
                   and a pre-written explanation. Numerical
                   questions state "take g = 10 m/s²" so answers are
                   whole numbers.

     FR-20         A correctly answered question is marked "cleared"
                   and not shown again.

     FR-21         A wrongly answered question shows its
                   explanation, which cannot be closed for 2 seconds,
                   and is marked "to review". It reappears later as its
                   variant: the same concept with a different scenario
                   or numbers. If the variant is also answered wrongly,
                   the original and the variant alternate until the
                   question is cleared.

     FR-22         A "Concepts cleared" screen lists cleared
                   questions with their explanations.

     FR-23         The game records how many times each question
                   has been answered, so it knows whether the
                   question was answered correctly on the first
                   attempt.

     ID            Requirement

     FR-32         Before every attempt, the student also predicts
                   the outcome of their own run: in Mission 1, the time
                   to reach the target (under 8 s, 8 s to 9 s, or over 9
                   s); in Mission 2, whether the rover crosses the ice
                   within 8 s and whether it coasts at least 17.5 m into
                   the sand; in Mission 3, whether it stops short of,
                   inside or past the zone. This prediction earns no
                   Knowledge. Stopping distance for the chosen build
                   is shown in the results, so the student can use it on
                   the next attempt.

     FR-33         Optional power-up questions appear at pickups on
                   the course. The simulation pauses while one is
                   shown. A correct answer gives a power-up for the
                   current attempt; a wrong answer has no penalty.

     FR-34         Optional unlock questions are available on the
                   build screen and earn Knowledge for
                   customization. Two unlock questions become
                   available for each mission concept once that
                   mission's required questions have been answered.



  3.8 Knowledge and progression

     ID            Requirement

     FR-35         Knowledge is earned the first time a question is
                   cleared. Required, power-up and unlock questions
                   all earn Knowledge points, at the values below.
                   There is no bonus for a first-attempt answer, so a
                   wrong first answer costs nothing but time. The
                   Knowledge balance is the points earned from
                   cleared questions minus the cost of everything
                   unlocked. No balance number is saved. The game
                   saves only which questions are cleared and what is
                   unlocked, and works out the balance from those
                   whenever it is needed, so the balance always
                   matches the progress.

  3.9 Progress saving and accounts

     ID            Requirement

     FR-24         The game saves, after each answer, the number of
                   times the question has been answered and, when
                   it is cleared, the time it was cleared. It saves each
                   unlock after the unlock, and a mission's completion
                   when the mission is cleared. A completed mission
                   is a safe point: the game resumes from it in the
                   next session. A question's status (cleared, to
                   review or unanswered), whether it was right the
                   first time, and the Knowledge balance are not
                   saved. The game works them out from this data
                   each time they are needed.

     FR-25         A signed-in student's progress is saved to their
                   account in a cloud database, with a copy in the
                   browser's local storage. A guest's progress is kept
                   in local storage only. Answers and mission
                   completions made without a connection are sent
                   to the account when the connection returns.

     FR-41         A student can play as a guest, or sign up and sign in
                   with an email address and a password. A signed-in
                   student can sign out, reset their password, and
                   delete their account together with all of its
                   progress. A new account starts with Mission 1 and
                   the three starting parts unlocked.

     FR-42         A student can read only their own progress. A
                   student can add or update only their own answers
                   and mission completions. Unlocks are recorded
                   only through the check in FR-44.




                                                                                             Page 15 of 24
Rovem — Software Requirements Specification




     ID            Requirement

     FR-43         At first sign-in, a guest's progress is copied into the
                   account if the account has none. If the account
                   already has progress, the student chooses which
                   of the two to keep, so Knowledge is never counted
                   twice. When two copies of the same account differ,
                   for example after playing on two devices, the
                   higher attempt count and the earlier clearing time
                   are kept for each question.

     FR-44         An unlock is recorded only if the Knowledge
                   balance covers its cost and, for a mission, the
                   previous mission is completed. The Knowledge
                   balance therefore never goes below zero. A signed-
                   in student needs a connection to unlock; a guest
                   unlocks on the device under the same rule.




  4. Non-Functional Requirements

     ID             Requirement

     NFR-1          Platform: runs in current desktop browsers. Mobile
                    browser support is a later phase.

     NFR-2          Performance: playable at 30 frames per second or
                    more on a laptop with integrated graphics
                    (proposed target). Physics results do not depend
                    on frame rate.

     NFR-3          Load time: low-poly models and compressed
                    assets keep the first download small (proposed
                    limit: 10 MB) so the game loads on slow
                    connections.

     NFR-4          Physics accuracy: automated tests compare
                    simulation output with hand-calculated values,
                    with a relative error below 10⁻⁹. The test cases are
                    listed in the Physics Model Specification.




                                                                             Page 16 of 24
Rovem — Software Requirements Specification




     ID             Requirement

     NFR-5          Extensibility: components, surfaces, terrains,
                    missions, questions and power-ups are stored as
                    data, so new ones can be added without rebuilding
                    the game.

     NFR-6          Clarity: only a few adjustable variables are shown
                    at once, and complexity increases gradually across
                    missions.

     NFR-7          Offline fallback: once loaded, the MVP works
                    without an internet connection, because all
                    explanations are pre-written. Signing in, saving to
                    the account and unlocking while signed in need a
                    connection; other progress is kept on the device
                    and sent to the account later (FR-25, FR-44).

     NFR-8          Privacy: the MVP collects only what accounts
                    need, which is an email address and the student's
                    progress. Guests provide no personal data. Any
                    playtest analytics are anonymous and used only
                    with the school's consent. Accounts for real
                    students are used only with the school's consent.




  5. Validation
       Physics: automated tests per NFR-4.
       Balance: all 27 part combinations are simulated against the mission limits (Component
       Values sheet). The starting build passes all three missions (FR-37), and every mission
       has builds that fail for a reason the explanation can name. Values are then tuned in
       playtesting.
       Progress data: automated tests check the Knowledge calculation (FR-35), the unlock
       rule (FR-44) and the merge rules (FR-43) against hand-worked cases.
       Learning (optional): a short pre/post question set (4–5 questions) and a small trial with
       a few students, recording first-attempt correctness per concept. First-attempt data
       alone is weak evidence, since students may learn from the run itself.

  6. Future Work (out of MVP scope)
       Three default rovers, and rovers designed by students using mass, weight and speed.
       Brakes become a fourth part slot, so brake force comes from a part.
       Student-made levels and challenges: terrain, planet and objectives, each with a visible
       cost or effect, so students see how environments change motion.
       Modifiers: in-game events (for example cannons, aliens or space weather) that each
       change one variable, such as mass, force, friction or velocity. Each shows its effect on
       screen.
       Momentum and impulse, which are in the Grade 9 Dynamics chapter, introduced
       through modifiers that change velocity by a force acting over a short time.
       Weight vs. mass through different gravity, only if it stays simple for Grade 9.
       More components, terrains and missions.
       AI helper that rephrases explanations and answers follow-ups using the run's data. It
       needs a server-side proxy so the API key is not exposed in the browser, and pre-
       written explanations stay as fallback.
       Mobile browser version with touch controls.
       Sharing of student-made levels.

  starts from is added to the action it points to only when its condition holds: progress is
  saved after viewing results only if the mission was completed.
