  How to read it
  Each box is one part of the game. A line between two boxes means they pass information
  to each other; an arrowhead shows the direction, and arrowheads at both ends mean both
  sides send information. The blue box is the physics. The orange boxes hold stored
  information: the game's content, the progress copy on the device and the cloud database.
  The dashed box is planned for later and is not in the first version. The three large panels
  show where each box runs: on the Rovem web server, on the student's own computer, or
  at Supabase.

  Read the browser panel from the top. The student uses the screens. The screens pass the
  student's actions to the game flow, which decides what comes next: questions,
  prediction, the run, then results. To run an attempt, the game loop moves the physics
  model forward in small fixed time steps and draws the result. The same physics model
  also fills in the Build screen's preview before a run, so the numbers the student sees there
  match what happens when they drive.

  The device always keeps a local copy of progress, and a guest uses only that copy. A
  student who signs in also uses Account and sync, which sends progress over the internet
  to the cloud database and brings it back on another device. The Supabase panel holds the
  database, the sign-in service and the delete-account function. That function runs in the
  cloud because it needs a secret key that must never reach the browser. The web server
  only sends the game files; later it will also run the AI helper's proxy.
