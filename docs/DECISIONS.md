(1) **Level file:** a level is a set of *roads*, each built from straight and arc segments (radius, ±angle) with a width and a run-off strip on each side; a point outside every road and its run-off is canyon wall. Terrain is hills (cosine bell: slope at most h π ÷ 2r), craters (flat floor, a wall at a constant angle, the gentle ramp within 45° of `rampHeadingDeg`) and ridges (rise angle, flat top, fall angle; used for the Gravity Wells 30° hill and the Polar Pass wall). (2) **Stop lines:** when the front crosses one, the rover is stopped at the line (speed and control levels to 0) for the red light, then goes; the clock keeps running. This is a game simplification so a fork starts from rest for both roads. (3) **Other-road time:** at the fork's merge circle a second session drives the other road from its start, from rest, throttle held, steering by pure pursuit along that road, and reports the time to the merge circle or how it ended (wall, barrier, stuck, floated, timeout). It is the same build and the same `step()`. (4) **Magnet bend:** the sideways push (sign × motion sign, as B1 said) is added to the travel direction each step; the tyres then pull the path back at most μ_g k_g R ÷ (m v). A respawn re-arms every pad, cannon, stop line and unfinished fork; samples and checkpoints stay. (6) **Stuck:** as in the run (full throttle, no brake, at rest), and a floating rover slower than 0.2 m/s counts as stuck (`floated`), because drag alone never reaches exactly 0. | 2026-10-18 | **Levels B1: how the new physics rules are applied** (provisional; implements `docs/LEVELS_BUILD_PLAN.md` A6; judgment calls by Claude where A6 is silent, for k._muz to veto). (1) **Slope sign:** `step()` takes the slope *along the gear* (positive = uphill the way heading × direction points), not along the motion. While a rover rolls back, uphill-along-motion is downhill-along-gear, so the gear-based sign keeps one number meaning one thing; the pull along the gear is −m g sin θ. A6's "θ along the direction the rover moves" is the same number whenever the rover moves along its gear. (2) **At rest:** pushing forces N = drive + slope pull + outside force along the gear; the rover stays if |N| ≤ hold, moves along the gear if N > hold, rolls back if N < −hold. A6 says hold = F_r. **Judgment call:** while the brake is on, hold = F_r + F_b, so a held brake keeps a parked rover from rolling down a ramp (A6 says brake only opposes motion; this is the same opposition at zero speed). With the brake off it is exactly A6. (3) **`externalForceN` now acts along the gear and can start a parked rover** if it beats F_r (before: moving rovers only, and clamped at top speed). Magnets use it. A magnet or a slope can carry a rover past its top speed; the motor then gives no force (A6; DECISIONS 2026-10-14 above-top-speed rule). (4) **Rolling back:** `rollingBack` is true while the rover moves opposite to its gear; `speedMps` stays ≥ 0. A rolling rover has no top speed. W still drives along the gear and S still brakes. Resisting forces never reverse the motion: a step that would cross zero stops at 0 and the at-rest rule decides the next step. **Judgment call:** steering is mirrored while rolling back, as in reverse (A6 is silent). (5) **Water:** `upthrustN` lowers R (never below 0); drag F_w = b v uses the speed at the start of the step (one explicit step, like the rest of the model). **Judgment call:** a floating rover (R = 0) cannot change its heading in `step()` (A6: "no turning"); the drift layer also gives it a turning limit of 0. (6) **Helpers:** `ground.ts` (R, slope pull), `water.ts` (submersion fraction, upthrust, drag coefficient, floats), `magnet.ts` (force by distance; split along the gear and sideways, sideways positive to the rover's left). In `drift.ts`: `travelTurnLimitFromNormalRadPerS` (ω_max = μ_g k_g R ÷ (m v); 0 when R = 0) and `sidewaysBendRadPerS` (F⊥ ÷ (m v), ignored below 0.5 m/s). The old `travelTurnLimitRadPerS` stays for the Endless Canyon. (6b) **Gear flip:** `slopeRad` and `externalForceN` are given for the gear at the start of the step; when S alone flips the gear at rest, `step()` turns their signs itself (found by physics-checker). **For the game layer (B2):** `magnetOnRover` gives `alongGearN` and `sidewaysN` relative to the gear; while `rollingBack` the rover travels opposite to the gear, so flip the sign of the sideways bend when `motionSign` is −1. In a step that splits at top speed, `accelerationMps2` is the start-of-step value. (7) **Nothing changes by default:** with no slope, water or outside force the new `step()` returns the same numbers bit for bit (tested over 1500 mixed steps); T1–T10, the M4 step trace and the balance counts (20/9/23/17) are unchanged. The only edit to an existing test: the M4 trace test now sets aside `rollingBack` (always false there), as it already did for `direction`. | Claude, A6 | B1, B2 |
